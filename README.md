# 书行万里 · Literary Atlas

> 读万卷书 · 行万里路

一款以世界文学为核心、以地理空间为探索线索的 AI 文学探索平台。用户可以在世界地图上发现文学作品及其关联的真实地点，管理个人阅读记录，并借助 AI 进行文学探索、作品识别与个性化推荐。

`Vue 3` · `Vite` · `FastAPI` · `SQLite` · `DeepSeek` · `自研 SVG 世界地图`

---

## 一、项目背景与设计理念

文学经典总是发生在具体的地理空间之中：马孔多的小镇、巴黎的街巷、伊斯坦布尔的城市记忆。**书行万里**尝试把"读书"与"行路"重新连接起来——以真实地理坐标为线索组织世界文学内容，让每一次阅读都能落在地图上的一个确切位置。

设计原则：

- **文学为核心**：项目服务于阅读与文学探索，不是旅游导航或旅行规划工具；地图是理解文学的视角，而非出行指南。
- **地理信息诚实**：只展示具有可靠地理信息的真实地点，虚构地点与无法核实的地点不以坐标形式呈现，避免地图信息失真。
- **公共与个人结合**：公共精选作品构成世界文学地图的底座，个人阅读记录在其上生成专属的文学足迹。

## 二、三大核心功能

### 1. 世界文学地图

- 在自研 SVG 世界地图上探索不同国家和地区的文学作品，支持地图缩放与地点聚焦。
- 查看作品、作者、文学类型及其关联地点，点击地点查看该地关联的全部作品。
- **同地点多作品聚合展示**：个人地图模式下，同一真实地点只绘制一个标记，点击可查看该地点关联的全部已读书目，不重复绘制标记。
- 地图仅展示具有可靠地理信息的真实地点；虚构地点不以地图坐标形式呈现。

### 2. 个人书架与文学足迹

- **阅读状态管理**：支持想读、在读、已读三种状态的添加、切换与删除。
- **阅读记录**：记录阅读进度、评分与笔记。
- **个人文学足迹**：根据已读作品关联的真实地点生成专属足迹地图，展示阅读经历与地理空间的联系。
- **阅读统计**：汇总各状态书目数量等个人阅读数据。

### 3. AI 文学探索

- **AI 对话探索**：通过自然语言与 AI 智能体交流作品、作家与文学地理话题，智能体可调用工具查询项目文学数据库，结合个人阅读记录给出回答。
- **作品推荐与探索辅助**：基于已有文学资料与个人书架提供推荐建议。
- **AI 辅助添加自定义作品**：在作品探索页输入书名（作者选填），AI 识别作品并生成草案（作者、国家或地区、类型、简介、文学关联地点），用户确认修改后才保存：
  - **同名歧义处理**：无法确定具体作品时返回候选列表，由用户选择，不随意猜测；
  - **重复检测**：已收录作品给出提示，可直接加入书架，避免重复创建；
  - **降级方案**：AI 检索不可用或无法识别时，可仅保存书名和作者；
  - **坐标诚实**：新作品的关联地点仅复用地点库中已核实的真实坐标，无法核实的地点不以坐标呈现，也不会进入公共世界地图；
  - 新增作品默认加入个人"想读"书架，并与公共精选作品以 `source` 字段明确区分。
- **对话记录会话保存**：AI 对话记录在当前浏览器会话中持久保存（切换页面、刷新后不丢失，关闭浏览器后自动清除），并提供带二次确认的清空对话功能。

## 三、项目特色与创新亮点

1. **世界文学数据库 × 地理空间可视化**：将文学元数据（作品、作者、类型）与真实地理坐标关联，用交互式世界地图呈现文学的空间分布。
2. **三维关联网络**：从作品、作者、地点三个维度建立文学探索关系，任一维度都可以作为探索入口。
3. **公共地图与个人足迹结合**：同一张地图上可切换世界文学总览与个人阅读足迹两种视角，个人阅读行为映射到真实地理空间。
4. **AI 深度接入且可确认**：AI 不仅用于对话问答，还辅助完成作品识别、信息补全与地点提取；所有 AI 生成内容经用户确认后才写入数据库，避免不可靠信息直接入库。
5. **地理信息诚信机制**：AI 只负责提取文学地点名称，不生成经纬度；坐标仅来自项目中经人工核验的真实地点库，虚构地点明确标记且不参与地图渲染。

## 四、技术栈

| 层级 | 技术 | 说明 |
|---|---|---|
| 前端框架 | Vue 3 + Vue Router | 组合式 API，自研轻量组合式 store 管理书架与地图状态 |
| 构建工具 | Vite | 开发服务器固定端口 5173 |
| 地图渲染 | 自研 SVG 地图 + `world.geo.json` | 无重量级地图库依赖，支持投影、缩放与标记聚合 |
| 后端框架 | FastAPI + Uvicorn | 提供 REST API 与健康检查接口 |
| 数据库 | SQLite | 单文件数据库，外键级联，无需独立数据库服务 |
| AI 能力 | DeepSeek（经 OpenAI 兼容 SDK 调用） | 智能体对话、工具化数据查询、作品识别与地点提取 |

## 五、项目运行环境与启动说明

### 环境要求

- Python 3（项目在 Python 3.14 环境下验证通过）
- Node.js 18+（含 npm）
- （可选）DeepSeek API Key：用于启用 AI 对话与 AI 辅助添加作品功能

### 1. 启动后端

```bash
cd backend
pip install -r requirements.txt

# 配置环境变量：复制模板并填写
#   Windows PowerShell:  Copy-Item .env.example .env
cp .env.example .env       # 编辑 .env，至少配置 DEEPSEEK_API_KEY

# 启动服务：默认端口 8000
uvicorn main:app --reload

# 或：使用自定义端口启动（本项目当前联调使用 8001）
uvicorn main:app --reload --port 8001
```

- 后端没有内置端口配置，端口完全由启动命令决定；不指定 `--port` 时 Uvicorn 默认使用 **8000**。
- 健康检查：访问 `http://127.0.0.1:<端口>/health`，返回 `{"status": "healthy"}` 即启动成功。
- **前后端端口必须一致**：无论后端使用 8000 还是其他端口（如本项目联调所用的 8001），前端 `VITE_API_BASE_URL` 都必须指向同一端口，否则前端将无法连接后端服务。
- 数据库首次使用：`literary_atlas.db` 不存在时，访问任意接口会自动建表；种子数据通过 `python seed.py` 手动导入（会写入正式数据库，仅在数据确认无误后执行）。

### 2. 启动前端

```bash
cd frontend
npm install

# 配置后端地址：复制模板并填写
#   Windows PowerShell:  Copy-Item .env.example .env
cp .env.example .env       # 编辑 .env，VITE_API_BASE_URL 指向后端实际地址和端口
                           # 后端默认启动（8000）：VITE_API_BASE_URL=http://127.0.0.1:8000
                           # 后端 8001 启动（本项目当前联调端口）：VITE_API_BASE_URL=http://127.0.0.1:8001

npm run dev
```

- 访问 `http://localhost:5173`。
- `VITE_API_BASE_URL` 留空时前端自动使用本地 Mock 数据（开发回退模式，页面可浏览但数据不来自后端）；也可设置 `VITE_USE_MOCK=true` 强制使用 Mock。

### 3. 前端构建

```bash
cd frontend
npm run build    # 产物输出至 dist/
```

## 七、数据说明

- **文学数据**：内置 50 部世界文学精选作品及作者、文学类型信息，覆盖多个国家和地区的代表性经典。
- **地理数据**：地点库包含城市、国家、地区三类真实地点，以及明确标记的虚构地点；真实地点坐标均经人工核验（核验记录见 `docs/PLACE_COORDINATES_REVIEW.md`），虚构地点不携带坐标、不参与地图渲染。
- **关联数据**：作品—作者、作品—类型、作品—地点（区分"故事发生地"与"文学描写地"）多表关联。
- **自定义作品**：用户通过 AI 辅助添加的作品以 `source = 'custom'` 与公共精选作品明确区分，可独立删除；删除时不影响公共作品库及被其他作品复用的作者、地点、流派数据。
- **阅读数据**：阅读记录（状态、进度、评分、笔记）与作品关联，驱动个人书架、阅读统计与文学足迹。

## 八、AI 模型配置说明

AI 能力统一由后端调用，API Key 只通过后端环境变量配置，不会出现在前端代码中。在 `backend/.env` 中配置（模板见 `backend/.env.example`）：

```env
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=DeepSeek 兼容接口地址
DEEPSEEK_MODEL=模型名称
```

- 未配置有效密钥或网络不可用时，AI 对话与 AI 检索无法使用；AI 辅助添加书籍提供降级方案，可仅保存书名和作者作为基础词条。
- AI 生成的作品信息（含地点提取）均需用户在前端确认后才写入数据库；AI 不生成任何经纬度数据。

## 九、当前版本说明

当前为竞赛开发阶段的本地运行版本：

- 代码托管于 GitHub 公开仓库，**尚未部署到公网服务器**，无公网体验地址；请按照本说明在本地运行。
- 按单用户产品形态设计：暂无用户注册、登录与多用户隔离机制，个人数据保存在本地数据库中。
- 已实现：世界文学地图（总览/个人双模式、同地点聚合）、书架与阅读记录管理、阅读统计、个人文学足迹、AI 对话探索、AI 辅助添加自定义作品（歧义处理、重复检测、降级保存）、对话记录会话级保存与清空。
- 设计边界：虚构地点与未核实坐标的地点不以地图标记呈现；自定义作品不进入公共世界地图；`backend/backups/` 为本地数据库备份目录，不纳入版本管理。
